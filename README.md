# wine app - демо модели «хорошее вино» (ДЗ-3, ММАД)

приложение на streamlit для модели из ДЗ-3: StandardScaler + LogisticRegression без весов, обучена на Wine Quality. модель в приложении не обучается, она просто загружается из `model.joblib`.

## файлы
- `app.py` - само приложение;
- `model.joblib` - весь пайплайн (scaler + логрегрессия), сохранен в ноутбуке в ячейке «Сохранение модели»;
- `config.json` - порог $t_{F_1}$ = 0.27, подобран на валидации (не на тесте);
- `test.csv` - тестовая выборка вместе с `target`;
- `requirements.txt` - версии библиотек.

## запуск
python **3.12** (проверял на 3.12.3).

```bash
python -m venv .venv
source .venv/bin/activate        # windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

откроется на http://localhost:8501. запускать можно и из другой папки (`streamlit run wine_app/app.py`), пути к файлам считаются от `app.py`.

`model.joblib` сохранен в scikit-learn 1.9.1, поэтому в `requirements.txt` стоит та же версия. с другой версией sklearn при загрузке будет предупреждение или вообще ошибка.

## вкладки
1. **одно вино** - вводим 12 признаков (диапазоны и значения по умолчанию - min/max/медиана по `test.csv`), получаем вероятность и решение при пороге из сайдбара.
2. **модельные метрики** - матрица ошибок, precision/recall/F1, ROC- и PR-кривые с точкой текущего порога. все пересчитывается при движении слайдера.
3. **файл с винами** - загружаем CSV без `target`, получаем таблицу с вероятностью и решением и скачиваем ее. если не хватает колонок или файл битый - выводится ошибка, приложение не падает.
4. **что выучила модель** - коэффициенты логрегрессии по стандартизованным признакам, зеленые - «за» хорошее вино, красные - «против».

## кэширование (4.5)
streamlit при каждом действии перезапускает скрипт сверху вниз, поэтому без кэша все читалось бы и считалось заново.

- модель - через `@st.cache_resource`: это один объект на весь сервер, всем сессиям отдается ссылка на него. модель мы только читаем (`predict_proba`), копировать ее незачем, а грузить с диска долго.
- `test.csv` и вероятности на тесте - через `@st.cache_data`: каждый вызов получает копию результата, то есть если кто-то поменяет таблицу, кэш не испортится. для модели `cache_data` не подходит - копия модели это сборка объекта из байтов на каждом перезапуске, почти то же самое, что читать файл заново.
- вероятности на тесте считаются один раз в `test_proba(_model, X)` (у `_model` подчеркивание, чтобы streamlit не пытался ее хешировать). при движении слайдера меняется только сравнение `proba >= threshold`, `predict_proba` заново не вызывается.
- если вызвать `joblib.load` без декоратора, модель будет читаться с диска при каждом действии пользователя (сдвинули слайдер - скрипт заново - модель заново): приложение тормозит и тратит лишнюю память.
